# Shiori Mail

**AI の相棒「栞(しおり)」が、メールの処理を手伝ってくれる**、自分専用の IMAP / SMTP メールクライアントです。

栞は、届いたメールを先に読み、大事なところに栞を挟むように、要約・仕分け・予定の抜き出しをしてくれます。探しものや返信の下書きも頼めます。栞が使うのは**このマシンの中のローカル AI だけ**で、メールの本文を外部の AI サービスへ送りません。

![受信トレイとメールの画面。栞による仕分け・スレッド要約・予定の抜き出しが表示されている](docs/screenshots/message.png)

## できること

### 読む
- IMAP で受信トレイと送信済みを同期します(スレッド表示つき)。最初は各フォルダとも新しい 100 通を取り込み、それより古いメールは一覧の最後から 100 通ずつ取り込めます
- HTML メールは無害化し、スクリプトと外部画像を止めた状態で表示します(外部画像は許可すれば読み込みます)
- メールの中のリンクは、すぐには開かず、**行き先を確かめる画面**を通して開きます。表示と行き先の食い違い・URL の `@`・IP アドレス・国際化ドメイン・短縮 URL など、フィッシングの手がかりを知らせます
- 受け取った添付ファイルは、画像・PDF・テキストなら新しいタブで開き、それ以外は保存できます

### 受信トレイを片づける
フォルダに振り分けず、**要らないものを隠して、対応が要るものだけを処理する**使い方を前提にしています。

- 仕分け(宣伝・迷惑など)を選んで、一覧から隠せます
- 返信したメールは自動で「返信済み」に、それ以外は「完了」ボタンで対応済みにできます。未対応のメールには印が付き、「未対応のみ」で絞り込めます
- 一覧に表示しているメールを、まとめてメールサーバのゴミ箱へ移せます(返信済み・完了のメールは移しません)。1 通ずつ移すこともできます

### 書く
- 新規作成・返信・転送(元の添付も付けられます)
- 宛先・Cc・Bcc は、やり取りしたことのある相手を候補に出します(宣伝・迷惑の相手や noreply のアドレスは出しません)
- ファイルの添付(合計 18MB まで)と署名
- 返信の引用は本文の下にたたんでおき、外すこともできます
- 書きかけは自動で保存し、「下書き」の一覧から続きを書けます
- 送信の前に、宛先と内容の確認を必須にしています(栞が見直して、気になる点を知らせます)

### 栞がしてくれること
| 機能 | 内容 |
|---|---|
| 要約 | 1 通の要約と、スレッド全体の要約 |
| 仕分け | 「要返信・情報共有・予定・請求・手続き・宣伝・迷惑」と、優先度(高・中・低)。迷惑は詐欺・フィッシングの疑いを含みます |
| やり取りの確認 | 未対応のメールについて、やり取りが終わっていそうかを判断して知らせます(完了にするかは人が決めます) |
| 予定・やること | 日時のある予定・締切・依頼を抜き出し、一覧にします |
| 探しもの | 言葉が違っても、意味の近いメールを探します(埋め込みによる意味検索) |
| 返信の下書き | 口調(丁寧・簡潔・カジュアル)を選んで下書きします。返信を書く横には、元のメールの要約と予定を出します |
| 件名の提案 | 件名が空のまま本文を書くと、件名の候補を出します |
| 送信前の見直し | 宛先・日付と曜日の食い違い・添付の付け忘れなどを確かめます |
| 先読み | 画面を開いている間、5 分ごとに同期し、新着を順に読んでおきます |

- 右側の「栞の働き」パネルに、読み進み具合・仕分けの結果・かかった時間を表示します
- 栞の結果には、かかった時間・トークン数・モデル名を添えます。便利さと待ち時間を見比べるためです

### 使うほど、あなたに合っていく仕分け
栞の仕分けは、まず**似たメールの仕分けから推定**します(検索用の埋め込みを使う近傍法。1 通あたり数ミリ秒)。次のときだけ、会話用モデルに聞きます。

- 似たメールの仕分けが割れているとき、見たことのない種類のメールのとき
- 「宣伝」と推定したとき(広告に似せた詐欺を見逃さないため)

仕分けを手本として育てるしくみ:

- 仕分けは画面で確定・修正できます。「完了」にしたメールの仕分けも確定として扱います。確定した仕分けは栞に上書きされず、似たメールを仕分けるときの手本として重く数えます
- メールをゴミ箱へ移しても、手本(埋め込みと仕分けだけ。本文は残しません)は残ります
- `npm run ai:eval` で、確定した仕分けを正解として、近傍法と会話用モデルの正解率を測れます

## 必要なもの

- **Node.js 22.13 以上**(`node:sqlite` を使うため。開発は Node.js 25 で行っています)
- **OpenAI 互換 API のローカル AI サーバ**(llama-server・LM Studio・Ollama など)
  - 会話用モデル: 開発では Gemma 4 12B(Q4_K_M)を使っています
  - 埋め込み用モデル: 開発では bge-m3 を使っています(日本語を含む多言語に対応)
- **macOS**(メールのパスワードをキーチェーンに保存するため)
- **パスキーに対応したブラウザ**(アプリを Touch ID で開くため。Safari・Chrome など)

## はじめかた

```bash
npm install

# AI の接続先を設定する(設定画面からも変更できます)
cp .env.example .env.local

# 開発サーバを起動する
npm run dev
```

http://localhost:3000 を開くと、最初にこの Mac のパスキーを登録する画面が出ます。Touch ID で登録すると、次からはそのパスキーでアプリを開きます(http://127.0.0.1:3000 で開いた場合も localhost へ移ります。パスキーは IP アドレスでは使えないため)。

続いて設定画面が表示されるので、メールアカウントを登録します(次の節)。登録したら「サーバと同期」を押すと、メールの取り込みに続けて、栞が新着を読み始めます(索引 → 仕分け → 予定の抜き出し)。

栞が使う AI の接続先とモデルは、設定画面の「ローカル AI」で変えられます。

| サーバ | ベース URL の例 |
|---|---|
| llama-server | `http://localhost:8080/v1` |
| LM Studio | `http://localhost:1234/v1` |
| Ollama | `http://localhost:11434/v1` |

llama-server のように会話用と埋め込み用でサーバが分かれる場合は、「埋め込み用のベース URL」に埋め込みモデルのサーバを指定します。

## メールアカウントをつなぐ

設定画面の「メールアカウント」に、アドレス・パスワード・IMAP / SMTP のサーバを入力します。「接続を確かめる」で、保存する前にログインできるかを試せます。

- **パスワードは macOS のキーチェーンにだけ保存**し、データベースや画面には残しません
- Gmail などでは、通常のパスワードではなく「アプリ用パスワード」が必要です(2 段階認証を有効にしてから発行します)
- IMAP 993・SMTP 465 以外のポートでは STARTTLS を必須にし、暗号化できなければパスワードを送りません
- 接続先かログイン名を変えたときは、パスワードの入れ直しを求めます(保存済みのパスワードを別のサーバへ送らないため)

**読み取り専用モード**(既定でオン)の間は、サーバのメールボックスに一切書き込みません。メールは取り込むだけでサーバに残り、既読・未読はこのアプリの中だけで記録します。送信もしません。

Gmail の例:

| 項目 | 値 |
|---|---|
| IMAP | `imap.gmail.com` / 993 |
| SMTP | `smtp.gmail.com` / 465 |
| 送信したメールの控えを保存 | オフ(Gmail はサーバが自動で保存します) |

## コマンド

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバを起動する(127.0.0.1 でだけ待ち受け) |
| `npm run ai:eval` | 仕分けの精度を測る(DB には書き込みません) |
| `npm run auth:reset` | パスキーとログイン中のセッションをすべて消す(パスキーを失くしたときの復旧用。次に開くと登録からやり直し) |
| `npm run typecheck` / `npm run lint` | 型チェックと lint |

## セキュリティとプライバシー

- 自分のマシンで 1 人で使う前提のアプリです。127.0.0.1 でだけ待ち受けるので、ネットワークに公開しないでください
- アプリを開くには **パスキー(Touch ID)** での本人確認が要ります。操作しないまま 30 分経つか、ログインから 12 時間経つとロックします。ヘッダーの「ロック」ですぐにロックすることもできます
  - パスキーは公開鍵だけを `data/mailer.db` に保存し、秘密鍵は Mac(iCloud キーチェーン)から出ません
  - 最初の 1 つだけは、ログインせずに登録できます。インストール直後は、誰より先に自分で登録してください
  - localhost 以外のホスト名で届いたリクエストは断ります(悪意あるサイトによる DNS リバインディング対策)
- 取り込んだメールは `data/mailer.db`(SQLite)に保存します。このマシンの他の利用者からは読めない権限(0600)にしています
- AI の接続先にこのマシンの外の URL を指定すると、設定画面で警告します。その場合、要約や検索のたびにメールの本文がその宛先へ送られます
- 書きかけ(下書き)もデータベースに保存します。ブラウザには残しません(ロック中に読まれないように)
- 受け取った添付は、HTML や SVG などスクリプトを含みうる種類をこのアプリの中では開かず、保存だけにします
- リンクの行き先を確かめる画面(`/link`)だけは、ログインなしで開けます。メールの表示枠から開いたタブにはログインの Cookie が付かないためです。この画面はメールのデータを読まず、URL で受け取った行き先だけを表示します

## まだできないこと

- 受信トレイと送信済み以外のフォルダ、アーカイブ
- 送信したメールの HTML 形式(テキストで送ります)
- メールのパスワードの保存(macOS 以外)
- 複数のメールアカウント

## 技術構成

Next.js 16(App Router)・React 19・SQLite(`node:sqlite`)・[ImapFlow](https://github.com/postalsys/imapflow)・[Nodemailer](https://nodemailer.com/)

```
app/          画面とサーバアクション、AI の API(app/api/ai)
components/   画面の部品
lib/mail/     IMAP の同期、SMTP の送信、メールの解析
lib/ai/       ローカル AI の呼び出し、プロンプト、近傍法の仕分け
lib/drafts.ts 書きかけ(下書き)の保存
scripts/      仕分けの評価
```
